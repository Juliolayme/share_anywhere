Dev handoff — behaviour
  • File pick renders name + size from metadata only; never hash or read the file on the UI thread.
  • Per-receiver state machine: connecting → transferring ⇄ paused / reconnecting → verifying → completed | failed | removed | cancelled. One receiver never blocks another.
  • Route per receiver: probe P2P → TURN relay → Cloud only after consent dialog; budget hit → status “budget”.
  • ETA shows “Estimating time…” until >3% and while reconnecting.
  • Default: a valid code / QR / link joins the session and starts receiving immediately — no Request access, no Approve. Sender sees receivers appear, can Remove (kick) each, or Close session.
  • “Require approval” (off by default) on the create-session screen, session screen and Settings › Transfer restores the approve/reject flow.
  • Session max 5 receivers; 6th join auto-declined with sender notice.
  • While sending, receiving or waiting: persistent “Keep Share Anywhere open — don’t close it so the transfer continues.” Web adds a beforeunload confirm; Android shows the same text in the ongoing foreground notification.
Dev handoff — clipboard
  • Requires account + trusted device key. Guests see the intro gate.
  • Incoming items never auto-write to the OS clipboard — only on Copy.
  • Web status: auto · best-effort · denied · unsupported · offline (queue) · paused. Never “Always syncing”.
  • Android: capture in foreground only; background → notification “Open Share Anywhere to sync clipboard”.
  • Sensitive heuristics (OTP, password fields, card numbers) → “skipped” item, not synced.
Dev handoff — keep screen on
  • Active while: session open & waiting, any receiver transferring, receiving, waiting for approval.
  • Released on: finish, all paused, cancel, close, app/tab hidden; re-acquire on return.
  • Web: navigator.wakeLock.request('screen'); if missing/denied show “keep this tab visible”.
  • Android: FLAG_KEEP_SCREEN_ON on the transfer window (no WAKE_LOCK permission needed).
  • iOS: isIdleTimerDisabled; still suspended if user leaves the app.
  • Setting “Keep screen on during transfers” default ON; banner pill toggles for current transfer only.
