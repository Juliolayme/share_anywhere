# ADR 0016: Android networking and API models

Status: Accepted (Phase 6, milestone 6.1, 2026-11-11)

## Context

The Android app talks to the same REST API as the Web (`docs/API.md`, `shared/protocol/openapi.yaml`). The phase file asks for a client generated from `openapi.yaml` and kept in sync by the `protocol` job, and leaves OkHttp + Retrofit versus Ktor to an ADR. Constraints:

- Every request carries the in-memory device access token; a stale token (`401 device_token_expired` / `device_token_invalid`) refreshes once and retries, and no other error does (`docs/ARCHITECTURE.md` §3.2, the Web's `DeviceClient`).
- Tokens and refresh secrets must never reach a log (`CLAUDE.md` §7).
- WebRTC signaling (milestone 6.3) needs a WebSocket client.
- The build and the CI cache should stay small; the local build environment has little disk.

## Decision

- **OkHttp 4.12 with kotlinx.serialization, no Retrofit, no Ktor.** `ApiClient` (`android/app/src/main/java/app/shareanywhere/data/api/ApiClient.kt`) is a thin coroutine wrapper: it builds the request from an `ApiOperation`, sets `Authorization: Bearer`, maps error bodies (`error`, `message`, `retry_after_s`, `Retry-After`) to `ApiException`, and maps I/O failures to `NetworkException`. Token handling (single-flight refresh, retry on a stale token) lives in `IdentityManager`, not in an interceptor, so the retry rule is explicit and unit-tested. OkHttp also provides the WebSocket client for 6.3 and MockWebServer for JVM tests.
- **No logging interceptor at all.** Nothing logs request lines, headers, or bodies, in debug or release.
- **Models generated by `scripts/protocol.mjs`, not openapi-generator.** `pnpm protocol` writes `data/api/Api.gen.kt`: one `@Serializable` data class per object schema (`allOf` merged, required fields non-null, optional or `nullable` fields `? = null`, `snake_case` names through `@SerialName`), typealiases for primitive schemas, and `ApiOperations` with every operation's method, path template, and `x-sa-access` level. Enums stay `String` with the allowed values in KDoc, so a value added by the server never breaks decoding. `pnpm protocol:check` fails when the file is stale, and `GeneratedSourcesTest` checks on the JVM that `ApiOperations` lists exactly the operations in `openapi.yaml`. Endpoint wrappers (`DeviceApi` in 6.1; sessions, transfers, account in later milestones) are hand-written over these models.
- **Base URL from `BuildConfig`.** Debug defaults to `http://10.0.2.2:8080` (the host as the emulator sees it) and `-Pbackend=` overrides it; release needs `-PreleaseBackend=https://…` and refuses `http` at configuration time and again in `ApiClient`. Cleartext is allowed only by the debug network security config, and only to `10.0.2.2`, `localhost`, and `127.0.0.1`.

## Alternatives considered

- **Retrofit.** Adds an interface per API group and a converter, but the generated models and `ApiOperations` already give typed paths; the retry-on-stale-token rule would still need custom code. Rejected as weight without benefit.
- **Ktor client.** Multiplatform is not needed (iOS is native Swift), and it pulls an engine plus plugins on top of OkHttp anyway.
- **openapi-generator (kotlin).** Needs a JVM tool in the `protocol` job, generates a large client with its own HTTP stack and serializer choices, and would duplicate the token logic. The in-repo generator is about 150 lines, covers the schema features `openapi.yaml` uses, and fails loudly on anything else.

## Consequences

- A schema feature the generator does not support (for example `oneOf`) becomes `JsonElement`; using one in `openapi.yaml` means extending `renderKotlinModels` and its test in `scripts/protocol.test.mjs`.
- Release builds need `-PreleaseBackend`; there is no default production URL in the repository.
