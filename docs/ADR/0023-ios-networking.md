# ADR 0023: iOS networking and API models

Status: Accepted (Phase 7, milestone 7.1, 2026-11-12)

## Context

The phase file asks for an API client generated from `openapi.yaml` with `swift-openapi-generator` and kept current by the `protocol` job. Android solved the same problem with the repository's own generator (ADR 0016): `scripts/protocol.mjs` renders models for every client and `pnpm protocol:check` fails on drift, in one Node job.

## Decision

- **Models generated by `scripts/protocol.mjs`, not by swift-openapi-generator.** `pnpm protocol` writes `ios/ShareAnywhereCore/Sources/SAAPIClient/API.gen.swift` beside the TypeScript and Kotlin outputs: one `Codable, Sendable, Equatable` struct per object schema (`allOf` merged, required fields non-optional, `snake_case` through `CodingKeys`, a public memberwise initializer), typealiases for primitive schemas, `JSONValue` for free-form values, and `APIOperations` with every operation's method, path template and `x-sa-access`. Enums stay `String`, so a value the server adds never breaks decoding. The schema `Error` becomes `ErrorResponse` so it does not shadow `Swift.Error`. `pnpm protocol:check` fails when the file is stale, so the `protocol` job keeps the Swift client current, which is what the phase file asks for.
- **`APIClient` is a thin `URLSession` wrapper**, the twin of Android's `ApiClient`: it builds requests from an `APIOperation`, sets `Authorization: Bearer` and `User-Agent`, maps error bodies (`error`, `message`, `retry_after_s`, `Retry-After`) to `APIError` and transport failures to `NetworkError`. The transport is a protocol, so tests use a fake. Token refresh (single flight, one retry on a stale token) lives in the app's identity manager, as on the Web and Android.
- **Nothing logs requests, headers or bodies.** Release builds refuse a cleartext base URL.
- **WebSocket signaling uses `URLSessionWebSocketTask`** (milestone 7.3), with the one-time ticket from `POST /v1/ws/ticket`.

## Alternatives considered

- **swift-openapi-generator.** It is a build plugin with three runtime packages (`swift-openapi-runtime`, `swift-openapi-urlsession`, `swift-http-types`); generated code would live only in DerivedData, so the `protocol` job (Node) could not check it, and it would bring its own transport and error model next to the token rules the app needs anyway. One generator for three clients keeps the contract check in one place.

## Consequences

- A schema feature the generator does not support (for example `oneOf`) becomes `JSONValue` until `renderSwiftModels` is extended along with its test in `scripts/protocol.test.mjs`.
